# ADR-0004：系统采用 Agent 全托管与策略式自治

- 状态：Accepted；服务器维护职责与事实冲突边界由 [ADR-0005](0005-server-maintenance-agent-harness.md) 修订
- 日期：2026-07-21

## 背景

用户确认主要 MCP 客户端为 Qoder、Hermes Agent 和 Codex，并要求知识库的日常运行全托管于 Agent，不设置人工介入步骤。此前草案中的人工复核、人工记忆审批和人工故障队列因此不再适合作为目标架构。

## 决策

1. Qoder、Hermes Agent 和 Codex 均通过同一标准 MCP 契约访问知识库；默认 stdio，可选仅绑定 `127.0.0.1` 的 HTTP 服务。
2. Agent 编排器负责创建工作项、读取最小上下文、执行任务、提交 closeout 并确认闭环完成。
3. 摄取、索引、质量校验、记忆晋升、冲突处理、重试、备份和重建均提供 Agent 可调用或可调度的接口。
4. 不以人工审批保障安全；使用不可变原件、能力分权、策略校验、隔离、审计、幂等和可重建性保障安全。
5. 无法自动证明安全或正确的内容进入 `quarantined` 或 `disputed`，不进入默认检索；治理 Agent 自动创建补证或修复工作项。
6. MCP 不暴露强制接受、物理删除原件或清空审计的工具。高风险操作使用 tombstone、版本取代和隔离，保持可逆。
7. 用户仍负责改变系统目标、数据外发许可和不可逆策略边界，但不参与日常运行审批。

## 原因

- 避免候选、失败摄取和冲突因等待人工而永久积压；
- 让三个 Agent 框架能够形成真正的任务—知识—记忆闭环；
- 将可靠性落实到服务端规则，而不是依赖某个 Agent 的提示词自律；
- 保留低 token、可审计、可回滚和来源优先原则。

## 后果

积极：

- 正常运行不依赖人工值守；
- 客户端可以替换，知识契约保持稳定；
- 每个自动决定都有机器可读 policy trace；
- 失败和不确定性被显式隔离，不会伪装成成功。

代价：

- 需要实现治理 Agent、租约、重试预算和死信/隔离队列；
- 自动策略必须有版本、测试和回滚；
- 多客户端并发需要幂等键、锁或乐观并发控制；
- 在真实资料尚未提供时，只能验证协议和合成场景，不能证明真实语料质量。

## 失败安全规则

- 策略引擎不可用时默认拒绝晋升，任务可完成但记忆保持 `candidate/quarantined`；
- 来源失效时自动将相关知识标为 `stale/disputed`；
- 连续重试超过预算后进入可查询隔离区并生成诊断工作项；
- 任何 Agent 都不能通过修改请求参数绕过保密、来源或状态机校验；
- 自动修复必须输出前后哈希、验证结果和审计事件。

## 0.5.0 修订

“冲突处理”在 0.5.0 中只指发现、登记、路由、披露、补证和把用户明确答案整理进正确文档，不包含 Agent 自主裁决事实真伪。服务器维护 Agent 只整理知识，不承担查询、回答、写作或项目任务推理；详见 [ADR-0005](0005-server-maintenance-agent-harness.md)。
