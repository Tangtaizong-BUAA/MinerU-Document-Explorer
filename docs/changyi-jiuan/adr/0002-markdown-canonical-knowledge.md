# ADR-0002：原始文件不可变，Markdown 为规范知识载体

- 状态：Proposed
- 日期：2026-07-21

## 背景

项目希望将既有资料 Markdown 化并长期维护，但 PDF、图片、Office、表格和音视频不能被 Markdown 无损替代。若只保存解析文本，会丢失版式、图像、公式、原始数据和证据价值；若数据库成为唯一真相源，又会降低可读性、可迁移性和版本审计能力。

## 决策

采用三层数据原则：

1. 原始文件是不可变证据；
2. Markdown＋frontmatter＋assets 是规范化、可维护的知识载体；
3. SQLite、FTS、向量和生成视图是可重建派生物。

结构化项目记录同样使用 Markdown frontmatter 保存，数据库只物化字段以支持筛选和检索。

## 原因

- 原始证据可核验；
- Markdown 便于人和 Agent 共同读写；
- Git 可以审计文本和规范变化；
- 相对资源链接可保留图片和表格；
- 未来可以更换索引、embedding 或数据库；
- 避免同时手工维护“数据库事实”和“文档事实”。

## 后果

积极：

- 可移植、可 diff、可重建；
- 人类不依赖特定 UI 才能读取知识；
- 数据库损坏不会摧毁知识本体。

代价：

- 需要稳定 ID、Schema、文件监听和迁移；
- 大型结构化数据不能全部塞入 Markdown；
- 需要处理文件编辑并发和 broken links；
- 原始大文件需要独立备份/LFS/对象策略。

## 约束

- 不删除已登记原始文件来“节省重复”；
- 不把生成 Markdown 描述当作图片本身；
- 不让自动生成视图反向覆盖正式记录；
- 任何 accepted 记录都必须能从文件恢复；
- 保密等级不会因摘要或转换自动降低。

## 待确认

该 ADR 在真实资料目录、容量和备份策略确认后转为 Accepted。
