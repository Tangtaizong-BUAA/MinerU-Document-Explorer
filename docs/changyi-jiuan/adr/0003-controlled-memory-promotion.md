# ADR-0003：Agent 记忆采用候选、校验和晋升流程

- 状态：Accepted；事实冲突闭合部分由 [ADR-0005](0005-server-maintenance-agent-harness.md) 修订
- 日期：2026-07-21

## 背景

用户希望 Agent 完成项目工作后通过 MCP 回传，并积累为新的记忆和知识。若 Agent 可直接写入正式记忆，一次误读、无证据推断或过期结论会持续污染未来回答。

## 决策

工作 closeout 和正式记忆分离：

1. Agent 通过 `kb_finish_work` 提交结构化结果；
2. 系统先保存事实性工作记录；
3. 可能复用的内容进入 memory candidate；
4. 依次执行 Schema、来源、判重和冲突检查；
5. 策略引擎根据证据强度、来源等级、适用范围、冲突和有效期自动决定 `accepted/quarantined/rejected`；
6. 解释性结论、经验和取代行为只有满足对应策略门槛才可自动接受，否则隔离并自动创建补证工作项；
7. accepted 记录通过 disputed/superseded 演进，不静默覆盖。

## 原因

- 阻断 Agent 幻觉的长期放大；
- 将“完成了什么”和“值得记住什么”分开；
- 能保留冲突和历史有效性；
- 支持 Agent 自动纠错、审计和回滚；
- 在零人工审批下仍阻止低证据内容进入默认检索。

## 后果

积极：

- 正式知识可信度更高；
- 失败任务也能诚实积累经验；
- 重试可通过幂等键安全处理；
- 决策变化可以解释。

代价：

- 需要可版本化的策略引擎和独立治理 Agent；
- 隔离项可能堆积，必须自动生成补证、重试或过期任务；
- 必须实现冲突和状态检索；
- MCP 本身不能保证 Agent 必然调用 finish，需要 Skill 和完成门禁。

## 自动晋升初始边界

可直接晋升：

- 文件和哈希验证；
- 测试/构建运行事实及日志引用；
- 合法、无歧义的状态迁移；
- 系统生成的时间与作业事件；
- 带有可认证用户指令来源的项目约束与偏好。

研究结论、人物或组织判断、长期方法和因果解释必须满足更高证据门槛；不能满足时进入 `quarantined`，而不是等待人工审批或直接接受。

## 不提供强制接受旁路

MCP 不提供 `force_accept`。治理 Agent 只能补充证据、请求重新校验、限定作用域或提交取代关系，最终状态仍由策略引擎计算并生成 validation event。

## 0.5.0 修订

上述自动晋升仅适用于没有形成事实冲突的候选。候选一旦与 accepted 知识形成语义冲突，策略引擎只能登记、隔离、路由和披露，不能依据来源排序或补证自行 supersede。冲突关闭必须来自明确的用户答案，并经过 revision、幂等和原义传播校验；详见 [ADR-0005](0005-server-maintenance-agent-harness.md)。
