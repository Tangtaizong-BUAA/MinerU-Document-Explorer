## B. 当前工作默认值

以下尚未被用户逐项确认，只为避免规划停滞：

| ID | 默认值 | 为什么安全 | 改变后的主要影响 |
|---|---|---|---|
| A-001 | 本地优先 | 最少外发和基础设施 | 远程部署需要认证、TLS、对象存储 |
| A-002 | 首期单维护者 | 权限模型仍保留但实现更轻 | 多人需要用户、角色、并发与冲突处理 |
| A-003 | 普通 Agent 只读 | 防止知识污染 | 开放直接写需更细粒度授权和回滚 |
| A-004 | 解释性记忆人工审批 | 防止错误长期放大 | 自动采纳需规则、风险等级和抽检 |
| A-005 | 原始资料默认不出本机 | 保护科研与人物资料 | 云 MinerU/模型需资料分类与明确同意 |
| A-006 | 中文为主，英文术语保留 | 符合当前项目语境 | 双语库需语言字段和评测集 |
| A-007 | 先文件＋SQLite，不上图数据库 | 可重建且复杂度低 | Graphiti/Neo4j 需同步和成本治理 |
| A-008 | 源码公开 fork，真实语料不入公开仓库 | 避免资料泄露 | 私有 fork 可调整测试与部署策略 |

## C. 需要用户确认的产品问题

### Q-001：首期协作方式

- 选项：仅本机个人使用 / 同一台机器多人使用 / 局域网或公网远程协作。
- 当前默认：仅本机个人使用。
- 最晚确认：远程 HTTP MCP 或管理界面实施前。
- 影响：认证、权限、部署、备份和审计复杂度。

### Q-002：真实资料的保密等级

- 需要知道：是否包含未公开科研、受访者身份、联系方式、单位内部材料、知情同意限制。
- 当前默认：全部按 `internal`，人物敏感字段按 `restricted`。
- 最晚确认：第一次真实资料 POC 前。
- 影响：云解析、模型选择、日志和公开测试数据。

### Q-003：现有资料规模与格式

- 需要知道：大约文件数、总容量、扫描 PDF 比例、图片数量、是否有音视频和 Excel 大表。
- 当前默认：首轮从 20～30 份代表性样本开始，不扫描整个磁盘。
- 最晚确认：Phase 1 inventory 前。
- 影响：存储、Git LFS、解析作业并发、模型和备份。

### Q-004：Agent 客户端优先级

- 选项：Codex / Claude Code / Claude Desktop / Cursor / 自建 Agent。
- 当前默认：首先兼容 Codex 与标准 MCP，保留其他客户端兼容。
- 最晚确认：Phase 3 MCP 实现前。
- 影响：stdio/HTTP、Skill、自动 closeout 和鉴权能力。

### Q-005：记忆自动接受策略

- 选项：全部人工 / 仅确定性系统事实自动 / 更广泛规则自动。
- 当前默认：仅文件哈希、测试结果和合法状态迁移等确定性事实可自动。
- 最晚确认：Phase 5 前。
- 影响：审批负担和知识污染风险。

### Q-006：总体信息维护界面

- 选项：Markdown/Obsidian / 本地表格 Web UI / 两者同时。
- 当前默认：文件为真相源，先自动生成 Markdown 表格；UI 后置。
- 最晚确认：Phase 2 后半段。
- 影响：前端工作量、双向编辑和冲突处理。

### Q-007：备份目的地

- 选项：外置硬盘 / NAS / 私有对象存储 / 加密云盘 / 组合。
- 当前默认：规划备份接口，不替用户选择物理目的地。
- 最晚确认：Phase 4/6。
- 影响：恢复时间、加密和离机容灾。

### Q-008：Fork 可见性与最终仓库命名

- 当前 fork：`Tangtaizong-BUAA/MinerU-Document-Explorer`。
- 需要确认：长期保持公开 fork，还是未来迁移到私有产品仓库。
- 当前默认：代码 fork 公开，真实数据和密钥永不进入仓库。
- 最晚确认：放入任何组织特有实现或测试材料前。

## D. 不需要阻塞当前文书工作的事项

- 最终 UI 技术栈；
- 是否引入 Graphiti；
- 是否用 RAG-Anything 增强图表问答；
- 远程生产部署域名；
- 最终 embedding 模型。

这些问题应由真实样本评测触发，而不是提前猜测。

## E. 决策升级规则

以下变化必须新建 ADR 并由用户确认：

- 原始资料的真相源位置改变；
- 允许未审批内容进入正式记忆；
- 允许数据默认外发云服务；
- 从单机扩展到远程多用户；
- 允许 Agent 直接覆盖 accepted 记录；
- 引入第二个不可重建的核心数据库；
- 改变 fork/上游同步策略。
