### D-003：遇到实质性不明确问题即时咨询

- 状态：Accepted
- 影响：可逆、安全默认值允许先推进；会改变部署、权限、数据外发或真相源的决定必须询问用户。

### D-004：主要 MCP 客户端

- 状态：Accepted
- 客户端：Qoder、Hermes Agent、Codex；同时保持标准 MCP 兼容，不将领域数据绑定到单一框架。
- 影响：生产使用带认证的标准 HTTP MCP 作为团队共享入口，stdio 保留为本地开发与兼容模式；三端均需通过 capability、structured output、resource link 和 closeout 互操作测试。

### D-005：Agent 全托管，正常路径零人工介入

- 状态：Accepted
- 依据：用户明确要求系统全托管于 Agent，不要人工介入。
- 影响：摄取、任务回传、无冲突记忆判断、冲突登记与路由、重试、重建和健康检查都必须有 Agent 可执行的闭环；不得把“等待人工运维审批”设计成正常状态。
- 安全边界：正式记忆不能由 Agent 任意强制写入。无冲突候选由确定性策略自动晋升、隔离或拒绝；事实冲突进入 `quarantined/disputed` 并随相关检索披露，服务器 Agent 不得自行裁决。用户只在需要决定真实语义时回答冲突问题。
- 记录：[ADR-0004](adr/0004-agent-managed-autonomy.md)

### D-006：历史资料暂缓接入

- 状态：Superseded
- 影响：该决定仅解释早期阶段。用户随后已提供并授权解析首批真实项目资料；合成 fixture 继续承担契约回归，但不能替代真实项目检索评测。

### D-007：家庭主写、阿里云只读回退

- 状态：Accepted
- 依据：用户确认全部团队成员通过统一线上 MCP 使用，主服务优先运行于家庭服务器，并以阿里云回退。
- 影响：家庭节点是唯一知识写者；阿里云负责 HTTPS 入口、主链路代理和家庭节点不可达时的 `project-read` 快照服务。禁止双写、自动反向合并和在回退节点运行维护 Worker。

### D-008：限定范围的 MinerU 与阿里百炼外发

- 状态：Accepted
- 依据：用户明确授权把已提供项目文件上传到 MinerU 云 API，并允许项目文本、页面图像和视频片段用于阿里百炼多模态索引与维护。
- 影响：原始与 canonical 文件仍保存在家庭主节点；外发按 Artifact、供应商、用途、模型和哈希审计。授权不扩展到未来任意敏感资料，API Key 永不写入仓库或知识文档。

### D-009：服务器维护 Agent 只整理知识

- 状态：Accepted
- 决定：服务器 Agent 不回答用户、不执行项目工作，只消费增量 ChangePacket，提出主文件、分文件、拓扑和冲突记录的结构化维护计划。
- 技术选择：MS-Agent 1.6 隔离 Python Worker 作为原生全模态循环内核，默认 `qwen3.7-flash`；外层由项目自有确定性 `KnowledgeMaintenanceHarness` 负责校验和提交。
- 记录：[ADR-0005](adr/0005-server-maintenance-agent-harness.md)

### D-010：事实冲突不得自动解决

- 状态：Accepted
- 决定：维护 Agent 只能发现、登记、补证、路由和披露冲突。来源排序、时间先后、新文件版本或模型判断都不能自动关闭语义冲突。
- 解决条件：本地 Agent 在相关任务中谨慎说明并询问用户；只有明确的用户答案可进入 `resolution_pending`，typed resolution 与原义补丁成功提交后才标记 `resolved`。结果可以是单方取代、双方按 scope 同时成立、双方否定、候选拒绝或继续开放，不能强迫用户选边。

### D-011：冲突解决权属于项目负责人和指定负责人

- 状态：Accepted
- 决定：只有项目负责人和被显式配置的指定负责人可以获得 `project-resolve` capability 并持久提交冲突答案；其他团队成员只使用 `project-contribute`。
- 临时回答规则：未授权成员面对冲突时必须看到冲突并向用户说明。其本地 Agent 可以依据用户当轮回复修正当前推理和回答，但不得调用持久解决工具，也不得把该回复放入 `kb_capture_context`、`kb_finish_work`、资源上传或其他变相回传路径。
- 身份实现：每位 resolver 使用独立 token/可验证 principal；服务端只存 token SHA-256 与角色映射。共享团队 token 不得拥有 resolve capability。

### Q-002：真实资料的保密等级

### Q-010：现有百炼 Workspace 地域

- 需要确认：当前准备使用的百炼 Workspace/API Key 是否属于华北 2（北京，`cn-beijing`）。
- 原因：`qwen3-vl-embedding` 当前官方模型表在北京地域，API Key、业务空间 endpoint 和模型列表不能跨地域混用。
- 当前目标：北京业务空间专属 endpoint；region、endpoint、API dialect、模型 ID 和 key reference 作为一个版本化配置 tuple。
- 若不是北京：需由用户选择新建北京 Workspace，或重新评测其他地域可用模型；不得在代码里静默降级。

### Q-011：私有原视频与原始音频边界

- 状态：视频部分 Resolved；音频部分保持后续决策。
- 结论：0.5 维护模型必须原生理解视频。优先用受控 Base64 data URI，超过安全传输阈值时才使用带 TTL 与审计的短时签名 URL；不得用关键帧替代原生视频理解。关键帧/转写仍用于索引与精准 locator。
- 音频：`qwen3.7-flash` 不被宣称为独立音频模型；新增原始音频理解/ASR 仍需另行选择 Omni/ASR 模型与外发策略。

## E. 决策升级规则

以下变化必须新建 ADR 并由用户确认：

- 原始资料的真相源位置改变；
- 降低自动记忆晋升的证据或冲突门槛；
- 允许数据默认外发云服务；
- 从单机扩展到远程多用户；
- 允许 Agent 物理删除原件、审计或 accepted 历史；
- 取消 Agent 全托管，重新引入必需人工审批步骤；
- 引入第二个不可重建的核心数据库；
- 改变 fork/上游同步策略；
- 允许服务器维护 Agent 承担用户问答或项目任务推理；
- 允许服务器 Agent、来源优先级或文件版本自动关闭事实冲突。
