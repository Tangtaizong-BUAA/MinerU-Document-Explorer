# 01 项目章程

## 1. 项目名称

长翼久安项目知识库与 Agent 持久协作系统。

## 2. 背景

长翼久安是一个科研工作与社会实践工作相互交织的长期项目。资料形态同时包含论文、报告、实验材料、访谈、会议、活动文件、图片、表格和过程性成果。普通文件夹只能保存材料，普通 RAG 只能临时检索材料，两者都不能完整表达：

- 项目总体状态和工作流；
- 人员、组织、地点与事件关系；
- 原始证据到结论、决策和成果的链路；
- 事实随项目推进发生的修订、失效和取代；
- Agent 完成工作后形成的可复用经验和正式记忆。

本项目将 MinerU Document Explorer 定向改造成上述系统，而不是构建面向任意客户的通用知识库平台。

## 3. 项目使命

建立一个本地优先、证据可追溯、Agent 原生、低 token、可持续积累的项目知识基础设施，使用户给出的目标和边界能由 Agent 围绕同一套资料、结构化记录与正式记忆持续执行。

## 4. 核心目标

### G1：资料完整保存与可追溯转换

原始文件保持不可变；每份派生 Markdown、图片资源、表格或转写结果都能追溯到源文件哈希、解析器版本和准确定位。

### G2：维护项目总体信息

用类型化记录维护项目、工作流、人员、组织、活动、实验、证据、结论、决策、成果、风险和任务，并自动形成表格、时间线和仪表盘视图。

### G3：为 Agent 提供精准、节制的上下文

通过 MCP 提供结构化查表、分层检索、文档目录和局部读取；默认不向模型发送整库、整篇文档或无关图片。

### G4：建立可信的知识增长闭环

Agent 完成一项工作后提交成果、证据、决策、经验和遗留问题；系统经过 Schema、来源、判重、冲突和策略校验后，对无冲突内容自动决定晋升、隔离或拒绝。事实冲突必须保留并随相关检索披露，只能由用户明确回答进入解决流程，不由服务器 Agent 自行裁决。

### G5：可运维、可审计、可重建

任何索引损坏都可以从原始文件、规范化 Markdown 和结构化记录重建；任何知识更新都能追踪责任主体、时间、来源和取代关系。

## 5. 首期范围

首期必须包含：

- PDF、常见图片、DOCX、PPTX、XLSX/CSV 的摄取规划；
- 原始文件清单、内容哈希和转换状态；
- 中文为主的 Markdown 规范化结果；
- 科研与社会实践统一领域模型；
- 本地全文检索、向量检索和精确章节读取；
- 查询、执行和治理 Agent 的 MCP 能力分离；
- 工作项开始/结束与候选记忆回传；
- 项目简报、总体信息表、时间线、决策表和风险表；
- 基础质量评测、审计日志和重建演练。

## 6. 首期非目标

首期明确不做：

- 面向多个无关组织的通用多租户 SaaS；
- 用生成后的 Markdown 替代或删除原始文件；
- 自动相信 Agent 的所有总结和推断；
- 默认把敏感资料上传第三方模型或云解析服务；
- 仅凭向量相似度生成无来源答案；
- 在没有真实语料评测前引入复杂图数据库；
- 在领域与 MCP 契约未稳定前优先开发重型前端。

## 7. 主要用户与角色

| 角色 | 责任 | 默认权限 |
|---|---|---|
| 用户/项目所有者 | 提供目标、资料授权、数据外发和不可逆策略边界 | 策略配置；不参与日常审批 |
| 查询 Agent | 查表、检索、精读和证据化回答 | 只读 |
| 执行 Agent | 执行工作项、产出文件并提交 closeout | 受控写入 |
| 摄取 Agent | 登记、解析、校验、重试和隔离资料 | 摄取与派生写入 |
| 治理/维护 Agent | 补证、登记和路由冲突、维护文档与失效链；不回答用户、不裁决冲突 | 策略受控治理 |
| 运维 Agent | 备份、恢复、升级、健康检查和审计 | 系统运维；无物理删除原件权限 |

同一 Agent 框架可以承载多个身份，但每次 MCP 会话必须绑定明确 capability profile；不得因“都是 Agent”而共享无限权限。

## 8. 设计原则

1. **证据先于结论**：事实回答必须能回到原始来源。
2. **原始与派生分离**：原始材料只读，派生内容可修订。
3. **文件是真相源**：规范知识以可读、可 diff 的文件保存；数据库是索引。
4. **结构优先于纯语义**：能按 ID、类型、时间、人员查到时，不先跑向量检索。
5. **最小上下文**：先摘要和目录，再局部读取，最后才读取大段原文或原图。
6. **策略写入**：Agent 只能提交候选或证据，不能绕过策略引擎直接改写正式事实。
7. **增量演进**：只重算受影响内容，保留版本和失效链。
8. **可逆决策**：首期优先选择本地、轻量、易迁移的实现。

## 9. 关键交付物

- 定向 fork 仓库与上游同步策略；
- 领域 Schema 与示例记录；
- 摄取清单和转换流水线；
- 项目型 MCP profile；
- 项目简报与结构化视图；
- 工作项回传和记忆晋升状态机；
- 合成契约 fixture、未来真实语料评测集与自动化验收；
- 安装、备份、恢复和升级手册。

## 10. 成功定义

项目不是以“能搜到东西”判定成功，而是同时满足：

- 原始材料无丢失，来源链完整；
- 结构化总体信息可以持续维护；
- 标准问题能检索到正确证据并引用准确；
- Agent 的默认检索上下文处于预算内；
- 工作结果能幂等回传，未通过策略校验的内容不会污染正式记忆；
- 索引可从文件完整重建；
- 上游升级不会破坏项目层核心数据。

量化阈值见 [08-acceptance-evaluation.md](08-acceptance-evaluation.md)。

## 11. 治理方式

- 产品决定通过 ADR 固化；
- 规范文件和代码共同进入 Git 版本历史；
- 原始大文件是否进入 Git，由容量与保密策略决定，但必须进入哈希清单和备份；
- 每个里程碑都由 Agent 生成退出报告并由独立验证任务复核，不能只以提交数量衡量；
- 正常运行、记忆晋升和故障恢复不设置人工审批；
- 用户只在事实冲突确实影响项目工作时提供语义答案；这不构成日常运维审批；
- 涉及数据外发、物理删除原件、降低策略门槛或开放远程权限的边界变更，才需要用户明确授权。
